# LanguageTrainer — руководство разработчика

Этот документ описывает установку, развёртывание, управление из командной строки, сборку и выпуск релизов LanguageTrainer. Документация по интерфейсу для пользователя находится в [README.ru.md](docs/manual/README.ru.md).

## Запуск в Windows

Портативная Windows-версия — основной настольный дистрибутив. Распакуйте её в каталог с правом записи и запустите `LanguageTrainer.exe`. Данные приложения отделены от встроенных ресурсов, поэтому замена файлов программы не требует замены базы.

Подготовка исходного Windows-комплекта в Linux:

```bash
./prepare_win64_build.sh
```

Затем в Windows:

```powershell
cd win64_build
.\build.ps1
```

В результат входят настольное приложение, backend, статические английский и русский README, локальные словари, данные WordNet и модель Argos для перевода книжных фрагментов.

## Запуск в Docker

Соберите образ:

```bash
docker build -t languagetrainer:0.5.0 .
```

Запустите его с постоянным каталогом данных:

```bash
mkdir -p data
docker run --rm -it \
  -p 8000:8000 \
  -v "$PWD/data:/data" \
  languagetrainer:0.5.0
```

Откройте `http://127.0.0.1:8000/`. База и настройки находятся в подключённом каталоге `/data`.

## Локальный запуск Python

Создайте окружение и установите зависимости:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

Запустите сервер:

```bash
.venv/bin/python dict.py server --host 127.0.0.1 --port 8000
```

Откройте `http://127.0.0.1:8000/`.

Для диагностики производительности добавьте `--debug`. Плавающая панель регистрирует каждый API-запрос и отдельно показывает обработку на Python-сервере, fetch/время до первого байта, передачу ответа, разбор JSON и отрисовку Vue. Там же видны размер ответа и самый долгий этап. При обычном запуске панели нет.

```bash
.venv/bin/python dict.py server --host 127.0.0.1 --port 8000 --debug
```

## Управление из командной строки

Инициализация базы:

```bash
.venv/bin/python dict.py server --init --name Alice --host 127.0.0.1 --port 8000
```

Список коллекций:

```bash
.venv/bin/python dict.py control --user Alice --list-collections
```

Создание и загрузка словаря:

```bash
.venv/bin/python dict.py control --user Alice \
  --create-collection --name "Business words" --type words --lang EN

.venv/bin/python dict.py control --user Alice --collection_id 4 \
  --load-words words.txt --lang EN
```

Обновление встроенного Vue и модели Argos для перевода книг:

```bash
.venv/bin/python dict.py control --update
```

Для работы с конкретной базой используйте `--database /path/to/file.sqlite3`.

## Локальные данные и зависимости

Приложение рассчитано на локальную работу:

- SQLite хранит пользователей, коллекции, прогресс, слова, reminders, meanings и цитаты.
- Vue находится в каталоге `vendor/`.
- Английские определения берутся из встроенных данных WordNet.
- Греко-русский поиск использует `elru.db`.
- Произношения берутся из локальных звуковых и Macmillan-ресурсов, когда они доступны.
- Argos Translate используется для необязательного перевода книжных фрагментов с английского на русский, но не для создания README.
- Поиск слов (выпадающая панель определений) обслуживается из `dictionaries.db` — заранее собранного SQLite-кеша распарсенных StarDict-статей. Файл коммитится в репозиторий и копируется как есть в сборки Docker и Windows. Пересобирать командой `python build_dictionaries_db.py` нужно только при изменении исходных StarDict-словарей (она читает их и перезаписывает `dictionaries.db` рядом). При отсутствии файла приложение откатывается к чтению StarDict напрямую.
- Книги можно переводить офлайн: при включении перевода фоновый воркер заполняет покусочный кеш перевода впереди позиции чтения, а перевод в режиме чтения берётся из этого кеша.

Страницы En и Ru — два независимых Markdown-документа, которые поддерживаются вручную и включаются в начальную страницу приложения. Переключение языка не выполняет сетевой запрос и ничего не переводит во время работы.

## Управление версией релиза

Версия приложения задаётся константой `APP_VERSION` в `dict.py`. Обновляйте её штатной командой проекта, проверяйте `--version`, заново собирайте `win64_build` и создавайте тег с тем же номером. Не редактируйте сгенерированный Windows-каталог как исходный код.

В Windows окно приложения использует включённый в ZIP Qt WebEngine. Упаковка копирует Python и исходники и добавляет готовый EXE-запускатель; Rust, Node.js и C++ Build Tools больше не нужны. Python, браузерный движок и библиотеки C++ Runtime входят в ZIP; WebView2 и .NET не требуются. При упаковке проверяются DLL и импорт из изолированного Python.
